# S3 и разрешение имени

S3 server внешний. Приложение не разворачивает MinIO и не выдумывает endpoint/IP.
Настройте endpoint HTTPS, region, bucket, access key, secret key и force path style.
Bucket создаётся заранее, права — PutObject в reports/*; приложению не нужен
DeleteObject/ListAllMyBuckets. Отчёты дублируются в PostgreSQL для локального просмотра.
S3 adapter подписывает PUT по AWS Signature V4, SHA-256, region/service scope.
Поддержка S3 session token/assume role и multipart upload пока отсутствует.

После каждого Trivy scan сохраняются исходный JSON report, CycloneDX JSON и SPDX
JSON. Ключи reports/<scan UUID>/<format>.json. Дедуп загрузок — active jobs key.
При ошибке документ остаётся в БД, storage_status=ERROR; job повторяется до лимита.
После исчерпания retry необходимо исправить настройки и повторно поставить задание
оператором БД (универсальная кнопка retry пока отсутствует). История не удаляется.

Для приватного CA: config/certs/s3-ca.pem, S3_CA_FILE=/app/certs/s3-ca.pem.
Проверяется и цепочка, и hostname. extra_hosts не меняет hostname TLS.
При virtual host style убедитесь, что DNS/сертификат покрывают bucket.endpoint;
S3_HOSTNAME override обычно используется с force path style.

S3_HOSTNAME/S3_HOST_IP необязательны. scripts/compose-s3.sh создаёт override лишь
если оба заданы и корректны; основной Compose всегда валиден без extra_hosts.
JSON override является валидным YAML Compose. Для последующих команд используйте
оба -f, включая restart/build/up. Не используйте ранее созданный override после
изменения окружения без его проверки/повторной генерации.

scripts/configure-s3-hosts.sh читает .env как данные либо принимает
--hostname / --ip. Отсутствие одного поля → без изменений. Domain labels/IP
валидируются; loopback/link-local/multicast/unspecified запрещены.
Обновляется только строка с marker `# RizenVuln managed S3`.
Чужая конфликтующая запись вызывает отказ; идентичная не дублируется.
Перед записью создаётся backup hosts.rizenvuln.<UTC>.bak (0600); hosts получает 0644,
выполняются flock/fsync и проверка getaddrinfo. --hosts-file предназначен для тестов.

Команда администратора, если прав текущего пользователя недостаточно:

```bash
sudo ./scripts/configure-s3-hosts.sh
```

Пароль sudo скрипт не читает и не передаёт. В данной сессии /etc/hosts не менялся.
S3 credential проверка не выполнялась; mock tests не заменяют реальную проверку.
