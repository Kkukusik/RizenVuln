# Правила RizenVuln
Rust-first: бизнес-правила находятся в crates/core, инфраструктура — в адаптерах.
Не переписывайте работающие модули без необходимости. Предпочитайте простые проверяемые изменения.
Не храните секреты в коде, тестовых снимках, логах и ответах API.
Изменения схемы — только новой PostgreSQL migration; сохраняйте историю сканирований.
Используйте типизированные входные DTO, параметризованный SQL, структурированные JSON-логи.
Проверяйте ошибки и покрывайте существенное поведение тестами.
Не отключайте TLS. Не запускайте анализируемые образы. Не монтируйте Docker socket по умолчанию.
Непроверенные URL должны проходить DNS/IP SSRF-проверку с закреплением адреса и без redirect.
Не меняйте пользовательскую инфраструктуру. Развёртывание — Docker Compose.
Проверки: cargo fmt --all -- --check; cargo clippy --workspace --all-targets -- -D warnings;
cargo test --workspace; cd frontend && npm ci && npm run build && npm run test -- --run.
Фактическое состояние и ограничения сохраняйте в docs/implementation-status.md.
